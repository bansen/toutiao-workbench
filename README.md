# 头条选题采集与 AI 草稿工作台：功能与实施说明

更新日期：2026-10-25

> 本仓库仅公开项目说明文档，不提供程序源码、Windows EXE 或云端在线服务。下文区分已有功能与后续分发方案。

## 1. 项目目标

提供单用户本地网页工具，完成以下流程：

**手动登录头条（需要时）→ 发现素材 → 条件筛选 → AI 生成草稿 → 人工核实与编辑 → 导出。**

界面参考点选式采集工具，采集条件和 AI 设置分区显示。体裁、领域、表达风格可多选；红色表示选中，再次点击可取消。时间、排序、长度和版本数使用单选。

不自动发布，不承诺流量、原创认证或创作者收益。

## 3. 采集能力与限制

### 数据获取方式

使用专用 Chrome 浏览器目录，通过 Playwright 读取渲染后的页面内容。需要登录时由使用者在专用窗口手动完成，不读取日常浏览器的会话目录。出现验证码、访问限制或明确登录要求时暂停，人工处理后恢复。

本实现不依赖头条官方内容采集 API，也不建设私有接口签名或逆向调用体系。是否存在可申请的官方接口及其授权范围，需要另行以平台官方资料确认；本项目不把官方 API 当作已有能力。

### 真实页面验证

2026-10-25 的本地验证记录：文章 10 条、微头条 10 条均读到可见文字正文，并对首条样本重复读取。文章样本包含 9 条搜索结果和 1 条首页入口；微头条为 10 条搜索结果。验证使用未登录的公开页面，不代表未来页面始终可访问。

| 字段 | 文章 | 微头条 |
|---|---|---|
| 标题、作者、链接、正文、发布时间 | 样本可读 | 样本可读 |
| 阅读量 | 未验证可读，相关筛选禁用 | 未验证可读，相关筛选禁用 |
| 评论量 | 搜索卡片明确显示时读取 | 搜索卡片明确显示时读取 |
| 点赞量 | 未验证可读 | 部分卡片明确显示时读取 |
| 图片文字、OCR | 不支持 | 不支持 |

字段缺失使用空值，显示“未知”，不补成 0、不推算。使用某指标筛选时排除未知记录并统计数量；排序时未知值排到最后。

领域通过明确标注的关键词映射发现内容，不宣称覆盖全站热门内容。搜索与推荐可能受页面布局、访问环境和账号状态影响，目前没有完成个性化程度对照实验。

## 4. 功能与交互

### 采集设置

- 体裁：文章、微头条，可多选。
- 领域和关键词：领域可多选；“不限”清除其他领域选择。
- 时间：3 小时、12 小时、1 天、2 天、7 天。
- 阅读量：设计保留 5000+、1万～5万、5万～10万、10万～20万、20万～50万、50万+；当前因字段不可读而禁用。
- 排序：发布时间、评论量，以及能力验证允许的其他指标。
- 默认每轮检查最多 30 个候选，展示已检查、已入选和被排除的数量。
- 多体裁、多领域分别搜索，共用本轮上限；候选额度按组合均分，上限须足够覆盖组合数量。
- 支持逐行导入头条链接、开始与停止采集、查看日志、查看保存正文和打开来源。
- 根据内容 ID 或规范化 URL 去重，重复采集更新指标及采集时间。

### AI 草稿设置

两种模式：

1. **单篇改写**：分别根据每篇所选素材生成。
2. **多来源成稿**：综合手动选择的 2～5 篇相关素材。

表达风格支持多选：正式、口语化、自媒体叙述、新闻式表达。每种风格分别生成所选版本数。例如，2 种风格 × 2 个版本会生成 4 篇草稿，并分别调用模型。

改写程度为轻、中、深；仅影响表达与结构，不代表原创认证。长度支持接近原文、精简、300／500／800 字；版本数为 1～3，默认 1。

每版保存标题、正文、来源、生成参数、模型名和生成时间。支持人工编辑、保存、复制及 Markdown／纯文本导出。提示要求保留事实，不编造引语或经历，单列待核实事项，并将来源正文作为不可信资料，不执行其中指令。使用者可补充自己的观点和经历。

当前不生成图片，不自动下载或复用原文配图。

### 定时任务

- 默认关闭，可选择每 30 分钟、1 小时或 3 小时执行。
- 默认只采集入库；开启自动成稿后，每轮最多处理 3 篇新增合格素材。
- 采集与模型调用串行执行，不重叠；上一轮未完成时跳过本轮定时触发。
- 电脑休眠或程序退出后停止运行；重启等待下一周期，不补跑错过轮次。
- 验证码或登录要求触发暂停，处理后手动恢复。
- 失败任务可重试，已成功生成的版本跳过，保留人工编辑结果。

## 5. 技术方案与本地运行

技术栈：Python 3.11+、FastAPI、SQLite、Playwright，以及普通 HTML／CSS／JavaScript。采集器使用已安装的 Google Chrome。

以下命令适用于已经获得完整项目源码的使用者；**仅克隆本说明仓库不能运行程序**。

```bash
cd toutiao-workbench
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -m workbench
```

浏览器访问 `http://127.0.0.1:8765/`，按 `Ctrl+C` 停止。后续启动进入目录、激活虚拟环境，再执行 `python -m workbench`。

### 使用自己的 API Key

编辑项目目录中的 `.env`：

```dotenv
LLM_BASE_URL=https://your-provider.example/v1
LLM_API_KEY=replace-with-your-key
LLM_MODEL=replace-with-model-name
```

需要兼容 Chat Completions 的模型服务。Base URL 填服务地址前缀，通常包含 `/v1`，不要追加 `/chat/completions`。保存后重启程序，在网页模型设置中测试连接；测试会实际调用模型并消耗相应额度。

采集本身无需配置模型。真实密钥不返回前端、不写入任务日志、不保存在 SQLite。主动生成时，所选来源正文会发送给配置的模型服务。模型超时、限流或服务端错误最多自动重试 2 次；无效、空响应明确报错，不用模拟文本代替。

## 6. 数据与接口

SQLite 保存素材、任务、草稿和设置。正文与互动指标保留各自来源及采集时间。

| 内容 | 本地位置 |
|---|---|
| 数据库 | `data/workbench.db` |
| 专用浏览器会话 | `data/browser/` |
| 模型配置和密钥 | `.env` |

退出程序后备份数据库，恢复时先停止程序。清除专用浏览器会话不删除已保存素材和草稿。

本地 API 包含会话启动与清除、状态查询、采集与导入、素材查询、生成任务、草稿编辑与导出、定时设置和模型连接测试。任务状态包含等待、运行、待人工处理、成功、部分失败、失败和已停止。

修改接口校验本地请求来源和专用请求头。当前是单用户本地应用，没有互联网用户登录和多租户隔离，不能直接作为公网服务开放。

## 8. 云端部署：后续评估

理论上可把网页、后端、数据库和浏览器任务部署到服务器，但现有本地版本尚未完成云端改造。本阶段保留本地方案，不进行云资源采购和部署。

云端主要需要解决：

1. 用户身份认证、HTTPS、权限控制和访问隔离。
2. 专用浏览器的远程可视化操作，供用户手动登录和处理验证码；服务器浏览器不能直接使用用户电脑上的登录状态。
3. 浏览器会话与密钥安全保存，多用户时分别隔离。
4. 持久化存储、备份、任务进程管理和服务器重启恢复。
5. 云服务器网络环境下的真实采集稳定性验证；本地可读不意味着服务器环境也可读。

不能仅把当前监听地址改成 `0.0.0.0` 就视为完成云端部署。若以后恢复该方向，应先验证云端浏览器登录和实际内容读取，再建设完整在线界面。

## 9. 验证与验收

已有本地记录：31 项单元测试通过，JavaScript 语法检查通过，浏览器集成测试覆盖多选与设置持久化、草稿生成、编辑、复制、导出和数据库重开。模型交互使用隔离模拟服务，不代表真实模型效果已验收。

重点检查：

- 指标单位、区间边界、时间筛选、未知字段处理。
- 相同素材去重、指标更新及重启后的数据保留。
- 登录要求、验证弹层与正文不可见时的暂停或错误处理。
- 定时任务串行、错过轮次不补跑。
- 模型超时、限流、空内容和部分版本失败后的重试。
- 单篇与多来源模式、来源保留、人工编辑和两种格式导出。

最终业务验收仍需配置真实模型，以真实素材跑通“采集 → 筛选 → 生成 → 编辑 → 导出”。采集覆盖率、推荐流量和创作收益不属于软件验收承诺。
