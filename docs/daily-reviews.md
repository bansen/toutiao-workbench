# 每日头条复盘

此模块只读采集绑定账号的全部微头条（含手动发表），并提供结构化内容实验。正式定时任务必须在真实采集验收通过后启用，未通过时保持关闭。它不会修改发布数量、排期、新闻占比、声明、事实检查或已排队正文，也不会自动修代码。

## 日期与运行

北京时间每天05:00复盘前一天，其他整点仅检查最近一次已经到期的报告。首次正式执行为安装后的下一个05:00；00:00～04:59仍以最近的05:00为界。离线只补最近一次，不补多日。已完成的账号/日期不会再次采集或实施策略。

本机需联网、保持可用且工作台和Codex运行，不调整电脑电源设置。未启用独立任务时，以下命令仅用于本地手动验证：

```sh
.venv/bin/python -m workbench.review_cli run --validation --wait
.venv/bin/python -m workbench.review_cli check --run --wait
```

具体可用参数以`--help`为准。CLI只连接127.0.0.1:8765，不另开浏览器或重复启动服务。

## 数据口径与隐私

采集只使用现有专用Chrome的可见页面，复用串行锁，逐行让发布任务优先。管理页覆盖全部分页，通过微头条公开链接确认平台ID；单篇数据抽屉读取流量、互动、粉丝和收益。0和“待更新/未知”严格区分。单篇页未明确验证累计口径时标记`unverified`，报告进入待处理，保留原策略，不启用任务。

逐帖正文、ID、截图及排行仅保存在本机`data/reviews`，72小时清理；匿名统计与策略记录30天。Codex只读取匿名特征、覆盖率、同龄同时间段汇总，不接收原文、逐帖标题或账号ID。后台数据存在更新延迟，较高版本App数据也可能低于真实值，不能当作最终收益或全平台表现。

## 实验与恢复

只接收白名单枚举和有界数值，禁止任意提示词、代码或发布参数。每天最多启动一个新实验，同时只保留一个实验。约20%的新稿试验，80%基线，新闻和工具分开；来源选择前冻结分组，补发/修整沿用原意图，锁定正文不会变更。

同一发表日、时段、上线时长和累计口径内匹配，每组至少5篇且1000展现。只有明确不支持展现时才可使用每组200阅读的备用指标。样本不足不调整；提升至少10%且点赞/收藏/分享不下降超过10%，两次有效复盘后纳入基线。下降至少20%或实际质量/越界问题回退。评论单独展示，不单独决定成功。

策略实施先保存持久化意图再写入。提交超时或崩溃可能已实施时转待核实，不盲目重复。版本冲突保持原策略。采集失败与口径不明不构成内容质量警报。

## 本地接口

修改请求须带与本机服务一致的Origin及`X-Workbench-Request: 1`。

- `POST /api/reviews/run`：`validation`、可选`target_date`，异步只读采集。
- `POST /api/reviews/check`：按启用状态和05点日期边界检查/补最近一轮。
- `GET /api/reviews/settings`、`PUT`同路径：状态与验收门槛后的启停。
- `GET /api/reviews/{id}`：任务状态。
- `GET /api/reviews/{id}/anonymous`：匿名汇总。
- `POST /api/reviews/{id}/finish`：有界发现/建议、单项`changes`和`expected_version`。真实验证模式不应用策略。
- `GET /api/editorial-policy`：当前版本和实验。
- `POST /api/editorial-policy/rollback`：校验版本后回退。

具体真实验证结果保存在本机报告，不提交原始数据、截图、会话、数据库或密钥到GitHub。
