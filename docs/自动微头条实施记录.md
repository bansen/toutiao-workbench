# 自动微头条实施记录

## 已确认需求

- 单账号本地运行，发布纯文字微头条；选题为民生、AI、科技。
- 北京时间每日 08:00～22:00；每日随机目标 24～30 条。
- 将允许时段均分为当天目标数量的段，每段随机安排一条，最小间隔 15 分钟。
- 每小时准备下一小时所需稿件；合格稿不足时跳过，不凑数量。
- 错过的时段不补跑；排期持久化，重启不重新抽签。
- 测试阶段每条由用户确认；真实测试通过后由用户开启自动模式。

## 实施顺序和验证门槛

1. 先在工具专用 Chrome 中手动登录创作者后台。
2. 核实账号识别、微头条编辑入口、纯文字提交、AI 声明和结果查询。
3. 使用真实来源生成测试稿，预览由用户确认后提交。
4. 核实平台结果与内容 ID，验证提交超时的结果核查。
5. 完成三个方向的真实测试后开放自动模式。

未通过真实页面验证时，不实现猜测选择器的发布流程，不开放自动模式。

## 数据与交付

沿用本地数据库与密钥配置；迁移前备份数据库。新增每日计划、事件去重与发布队列；浏览器会话和数据库不进入版本管理。完整功能验收后更新说明并同步 GitHub。

## 离线排期模块

`generate_daily_plan` 生成 JSON 可序列化的每日计划；`expire_missed_slots` 在恢复运行时标记错过的时段；`next_scheduled_at` 查询下个有效时间。上述函数不会打开浏览器或发布内容。

`MicroPlanStore.get_or_create` 在事务内持久化每日计划，重复调用与重启均不重新抽签。时间输入必须带时区，统一转换为 Asia/Shanghai。未来运行时需在等待下个时间点前取得计划，正常唤醒时执行对应时段；恢复和休眠后的过期清理使用独立的跳过流程，不能在每个发布轮询中先清除刚刚到期的时段。

代码位于 `feature/auto-micro-publishing` 分支。正式版本保持不变，待真实发布验证通过后继续集成。

## 真实模型网络验证

运行环境存在 SOCKS 代理。已将依赖更新为 `httpx[socks]`，并在项目虚拟环境中验证真实模型请求。缺少代理依赖时返回可操作的错误提示，避免服务器内部错误及网络配置细节泄露。

## 声明核对的补充保护

新增声明状态检查辅助函数，要求原生复选框状态与可见组件选中样式一致，并同时满足“首发关闭、引用AI开启”；不一致时阻止提交。这只是待接入发布器的保护模块，不能视为已通过真实发布验收。


## 发送前去重

新增持久化发布历史与发送边界模块。已有确认测试稿从本机正文快照和核实回执导入；只接受账号、正文 SHA256 一致的已发布记录。新增表前备份数据库。

- 来源链接规范化后永久查重；正文去除标点、空白及来源行后查重，三字符片段 Dice 相似度达到 0.82 时拦截（正文至少 20 字，长度比至少 0.82）。
- 跨来源同一事件由模型逐批检查全部已记录历史；无法判断、有新进展需人工核实、服务失败时均不放行。模型判定不能保证完全识别所有重复事件。
- 历史包含已提交、已发布、审核未通过及结果待核实的作品。提交前在事务中锁定正文快照；提交异常保留为结果待核实，禁止盲目重发。重启保留锁定状态，不恢复自动发送。
- 草稿编辑页提供“发送前查重”，修改正文后结果失效。查重按钮不会发送，也不会占用发布名额。
- 发送边界要求账号和确认正文一致、首发原生状态与可见样式均关闭、引用AI均开启；状态缺失或不一致立即停止。时间限制在提交前再次核对。
- 去重范围仅限本工具已记录的作品；尚未同步的手工发文不在范围内。语义检查会产生模型调用费用，随历史增长逐批检查。

上述发送边界已通过模拟测试，尚未连接正式浏览器发布器；自动模式仍关闭。不得将查重通过视为发布能力验收通过。

当前去重增量完成 82 项自动化测试、Chrome 界面集成测试及真实已发布稿查重验证；账号或历史回执未核实的保护统一在发送边界执行。


## 自动发布开关（2026-10-30 更新）

按用户最新要求增加“自动微头条”面板和“自动发布”开关，新安装默认开启，手动关闭后保留设置，重启不重置。此要求替换此前“开关默认关闭”的设计。

通过本机 GET／PUT `/api/publishing/settings` 读取和保存；修改请求沿用本地来源检查，仅接受严格布尔 enabled。设置与实际运行状态分开：当前发布器和运行时排期尚未接入，服务端始终返回 ready=false、running=false；开关开启时页面明确显示“设置已开启 · 未就绪，未运行”。开关不触发发布，也不将既有测试视为完整发布能力验收通过。运行条件是否满足由服务端判断，客户端不能提交 ready 或 running。


## 自动执行链接通（2026-10-30，替换此前未接入状态）

已接通持久计划、不可变队列、自动备稿、发布前来源复查、发送边界及实际浏览器发布器。浏览器逐页串行，发布优先；模型检查不占浏览器锁。关闭开关、即时暂停、账号/声明设置变化在最终点击前复查。暂停有持久修订号，较早启动的验证不会覆盖较新的人工暂停。

当前用户选择“引用AI”关闭，实际账号已在真实页面核对首发及引用AI均未选中。旧公开作品不修改。若平台自行显示AI标识或意外首发，回执保留真实已发布状态，同时暂停后续。稿件若处于审核中，单独记录已提交，不把公开页暂不可见当作可以重发的失败。

已提交、已发布、审核未通过、结果待核实分开记录；程序退出恢复不会重发。编辑队列草稿作废旧排期，重新来源检查和确认后只能排未来未占槽。确认、拒绝、核查、暂停和恢复接口沿用本地来源限制。首次使用可显式绑定当前专用会话账号，既有绑定不会自动更换。

隔离Chrome夹具验证编辑器正文、声明、单次发布点击、作品记录与公开正文核查；真实编辑器验证处理Chromium空段落引入的额外视觉换行，保留词间空格，保存正文摘要及原始编辑器摘要。已有一条人工确认作品仍作为历史；新自动排期不提前加塞，只按已保存时间执行。

本轮通过160项离线自动化测试、隔离发布器Chrome夹具测试和真实工作台桌面／手机布局核对。代码同步到日常启动目录与main分支，浏览器会话、模型配置与数据库沿用原有本地目录。首次新自动排期的真实提交结果仍以运行日志及平台回执为准，不能将未到时的排期称为已经发布。

针对真实候选常含传闻或无支持引语的情况，有疑点初稿最多尝试一次删除问题内容的修订，保留初始核实问题供之后独立检查；修订失败时保留原核实项，不自动放行。不能只清空verify，不凭空补充事实，不保证每天能取得足量合格稿。

最终增量含修订失败保护与删改后独立核实测试，共162项离线自动化测试通过。
