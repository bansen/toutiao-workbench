# 模型用量与优化

当前生成一篇合格帖子可能包含生成、独立事实审核、一次修稿及复审。历史版本还包含事件及队列去重，现已移除。不能把草稿数或发帖数直接当成模型调用次数。

## 当前规则：移除内容去重

按用户要求，已移除模型事件去重、历史正文／相似度／来源重复拦截及界面查重入口。不会向模型提交发布历史或队列历史。不同发布任务允许使用相同来源或正文；同一任务的队列领取、提交锁、历史回执幂等仍保留，结果不明时只读核查、不重复点击发布。素材数据库仍按内容ID／规范化URL更新同一素材记录，属于存储规则。

DeepSeek官方服务的deepseek-flash／deepseek-v4-pro保留思考审核，但显式使用low强度；其他兼容服务不发送DeepSeek专有参数。依据：[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 仍保留的输入优化

- 修稿请求只携带待改正文、疑点和审核线索，当前完整证据单独传入，避免在草稿内部再夹带一份来源和内部记录。
- 事实审核中，初始来源与当前来源的URL、标题、作者、时间和正文完全一致时，正文只发送一次，并显式说明初始证据复用关系。有任意差异时仍提供两份完整正文。
- 已读取当前来源且正文与证据哈希一致、审核策略一致、凭据未超过三小时时，复用已有事实审核；来源的新鲜度和本地格式检查继续执行。证据变化、正文编辑、待核实项或凭据过期均需重新检查。
- 固定编辑规则保留稳定的system前缀，当前北京时间移入用户JSON的末尾。是否命中提供商缓存由实际服务决定，不承诺固定折扣。

以上不改变每日目标、新闻比例、发布时间、事实门槛、发布间隔和声明设置，也不自动降低模型质量或减少审核。

## 本地统计

运行中的模型客户端把每次HTTP尝试记入 `data/model-usage.jsonl`，区分 `generate`、`fact_check`、`repair`；旧记录中的 `dedup` 是已移除的去重调用。统计文件不进入GitHub。

只记录时间、环节、模型名、输入字符数、HTTP状态和提供商返回的token计数（如输入、输出、总量及缓存命中）。不记录API Key、正文、提示词、来源链接或响应正文。额外记录最终内容与思考内容的字符数及结束原因，用于识别思考开销和截断，不保存其文本。返回无效JSON但HTTP已返回时，仍记录服务端token；超时、取消或提供商未返回usage时，计数为未知，不能记作0或自行估算账单。

记录在启动后的首次写入及跨小时写入时清理72小时之前的数据；文件权限为600。统计写入失败不会放行检查失败的稿件，也不会阻断原有发布保护。

历史版本没有保存逐次usage，无法准确追溯各环节历史费用。离线字符压缩比例仅用于说明输入重复程度，不等于最终token或账单节省比例。应在新版本运行后，按环节汇总实际usage，再与提供商账单核对；未知请求需单列。
